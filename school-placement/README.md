# Оценка вариантов размещения школ

Локальное веб-приложение к практике 2 (Высоцкое городское поселение). Оно оценивает обеспеченность
населения местами в школах по кварталам. Пользователь размещает новые школы вручную, а приложение может
подобрать квартал для одной школы перебором всех кварталов.

Приложение не выбирает земельный участок и не оценивает возможность строительства. Для этого нужно
отдельное градостроительное обоснование.

## Запуск

Из корня репозитория, в окружении `.venv` практики 2 (там уже установлен BlocksNet 1.0.0a9):

```powershell
.\.venv\Scripts\python.exe school-placement\run.py
```

Браузер откроется сам: http://127.0.0.1:8000/. Если порт занят, приложение берёт следующий свободный
и печатает адрес в консоли. Остановка: `Ctrl+C`.

Параметры: `--port 8080`, `--no-browser`, `--data-dir <папка>`, `--verbose`.

Новое окружение (Python 3.10–3.12):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r school-placement\requirements.txt
```

## Данные

Приложение работает на сохранённых файлах из `data/` и ничего не скачивает. Папку `data/` собирает скрипт
подготовки. Он только читает результаты практики 2 и не меняет их:

```powershell
.\.venv\Scripts\python.exe school-placement\tools\prepare_data.py
```

| Что нужно | Откуда (examples/vysotsk/data/…) |
|---|---|
| Кварталы, `_id`, геометрия | `results/vysotsk_blocks_summary.geojson` |
| Население кварталов | столбец `population` (BlocksNet `impute_buildings` + `aggregate_objects`) |
| Вместимость существующих школ | столбец `school_capacity`: одна школа OSM, 250 мест, квартал №24 |
| Матрица времени в пути пешком | `accessibility_matrix_walk.parquet`, 255 × 255, минуты |
| Норматив и радиус | `blocksnet.config.service_types_config["school"]`: 120 мест на 1000 жителей, 15 мин |
| Сохранённые результаты для сверки | `results/provision_report.csv`, `results/provision_links.parquet`, столбец `school_provision` |

Если какого-то файла нет, скрипт перечислит недостающие файлы и укажет раздел ноутбука
`vysotsk_study.ipynb`, который их создаёт. Ноутбук берёт кэш из `data/` и скачивает только отсутствующие слои.

## Собственный набор данных (data_user)

Приложение может работать на собственном наборе слоёв по Высоцку (папка «Высоцкое городское поселение»:
`blocks.geojson`, `building.geojson`, `Cервисы/school.geojson`, `landuse.geojson`, `boundary.geojson`).
Ноутбук практики 2 по условию не меняется. Вместо него используется скрипт, который выполняет те же
шаги BlocksNet на этих слоях:

```powershell
.\.venv\Scripts\python.exe school-placement\tools\build_user_dataset.py --download-graph --source "D:\иду лекции\Данные по Высоцку\Высоцкое городское поселение-20261102T213450Z-1-001\Высоцкое городское поселение"
.\.venv\Scripts\python.exe school-placement\tools\prepare_data.py --source school-placement\sources\user_vysotsk --output school-placement\data_user
```

- Кварталы берутся из файла как есть: 473 штуки, мелкие **не объединяются**. `_id` — номер строки файла.
- Население берётся из зданий (столбец `population`, 1135 чел.), а не досчитывается BlocksNet.
  Агрегация по кварталам делается через `aggregate_objects`.
- Школа: МБОУ «Высоцкая ООШ», 340 мест (вместимость из файла).
- Матрица времени в пути строится через `calculate_accessibility_matrix` по пешеходному графу,
  скачанному по границе набора (`--download-graph`, тем же способом, что в разделе 8.1 ноутбука).
  Граф сохраняется в `sources/user_vysotsk/data/graph_walk.pickle`, и повторные сборки его не скачивают.
  Без этого ключа и без сохранённого графа используется граф практики 2.
- Обеспеченность считается через `competitive_provision(table, matrix, 15, 120)`, как в разделе 9.5 ноутбука.
- Тип землепользования квартала — «Тип» зоны из `landuse.geojson` с наибольшей площадью пересечения.
- Папка `Сценарий/` не используется.

Если `data_user` подготовлен, приложение по умолчанию открывает его. Выбрать набор явно:
`run.py --dataset user` или `run.py --dataset practice2`. Сохранённые сценарии хранятся
отдельно для каждого набора.

Результаты на этом наборе:
- Исходное состояние: потребность 159 мест, удовлетворено 137, дефицит 22 места, обеспеченность 0,862.
- Автоподбор школы на 600 мест: 24 равноценных лучших квартала, у каждого дефицит сокращается на 17
  мест (до 5).
- Ограничение: населённые кварталы 465 и 470 (7 жителей) лежат в 1,3–1,4 км от ближайшего узла
  пешеходного графа. Дороги рядом с ними (и в OSM, и в `roads.geojson` набора) образуют отдельный
  участок сети, не связанный с основной. `osmnx`/iduedu оставляют только связную сеть, поэтому граф
  по границе набора совпал с графом практики 2 (607 узлов, 1644 ребра). Время в пути для этих
  кварталов считается от ближайшего узла без учёта подхода к нему. На исходный результат это не
  влияет (до школы больше 15 минут при любом расчёте). В автоподборе школа рядом с ними может
  учитываться чуть оптимистичнее, примерно на 2 места. Приложение показывает это предупреждение.

## Метод

Расчёт тот же, что в разделе 9.5 ноутбука:
`competitive_provision(table[population, capacity], matrix_walk, 15, 120)` из BlocksNet 1.0.0a9.

- Потребность квартала: `ceil(население / 1000 × 120)` мест.
- Сначала потребность закрывают школы самого квартала. Остаток вместимости распределяется между
  кварталами в пределах 15 минут пешком. Распределение задаёт задача линейного программирования,
  то есть учитывается конкуренция кварталов за места.
- **Дефицит мест** = потребность − удовлетворённый в пределах доступности спрос.
  Это не «потребность − вместимость». В исходном состоянии вместимость 250 мест больше потребности
  181 место, но дефицит всё равно есть: 93 места, потому что школа недоступна части населения.
- Новая школа добавляет свои места к вместимости своего квартала. Население, матрица и норматив
  остаются исходными.

При каждом запуске приложение заново считает исходное состояние и сверяет его с практикой 2:
обеспеченность всех 24 населённых кварталов, итог 0,486 и 18 связей «квартал → школа». Если хоть
что-то расходится, приложение не запускается и объясняет причину.

## Возможности

- Карта кварталов в трёх режимах: «Исходное состояние», «Сценарий», «Изменение». Есть легенда,
  подсказки и маркеры существующих и новых школ.
- Карточка квартала: население, потребность, вместимость школ, обеспеченность, дефицит.
- Сценарий из нескольких школ, кнопки «Рассчитать сценарий» и «Сбросить изменения», выгрузка
  таблицы кварталов в CSV.
- «Разместить автоматически» (по умолчанию 600 мест). Сервер в фоне перебирает все 255 кварталов,
  каждый вариант считается от исходной сети школ. Интерфейс показывает ход перебора, остановку,
  ошибки отдельных кварталов и таблицу всех вариантов. При нажатии на строку сценарий показывается
  на карте и проверяется ручным расчётом. Равноценные лучшие варианты показываются все. Если перебор
  неполный, лучшим вариантом среди всех кварталов ничего не объявляется.
- Сравнение трёх вариантов с одинаковым приростом мест: A — одна школа в выбранном квартале, B — две
  школы в двух кварталах, C — одна школа в квартале, найденном автоподбором. Вместимость задаётся
  полем «Вместимость новых школ в каждом варианте, мест». По умолчанию 600 мест (300 + 300), как
  в задании. Кнопка «По исходному дефициту» подставляет дефицит территории. В варианте B вместимость
  делится поровну и её можно изменить вручную, но сумма должна совпадать с вместимостью варианта.
  При смене вместимости рассчитанные варианты помечаются как устаревшие. Кнопка «Рассчитать A, B и C»
  считает все три варианта; для C автоподбор запускается с этой же вместимостью.
- Сохранённые сценарии хранятся в браузере (localStorage); есть таблица сравнения и выгрузка в CSV.

CSV выгружается с разделителем `;`, десятичной запятой и в UTF-8 с BOM, поэтому корректно открывается
в Excel с русской локалью.

Результат для школы на 600 мест на данных практики 2: лучший квартал №22, дефицит сокращается
с 93 до 5 мест (на 88), вариант единственный. Квартал с наибольшим собственным дефицитом (№1, 86 мест)
даёт сокращение на 87 мест. Школа в квартале №22 закрывает потребность квартала №1 и ещё одного
соседнего квартала в пределах 15 минут. Поэтому перебор нельзя ограничивать кварталом с наибольшим
собственным дефицитом.

## Проверки

```powershell
cd school-placement
..\.venv\Scripts\python.exe -m pip install pytest
..\.venv\Scripts\python.exe -m pytest tests -p no:cacheprovider
```

Тесты в `tests/` покрывают:

- воспроизведение исходного результата: по кварталам, итог и связи; пустой сценарий совпадает
  с исходным состоянием;
- соответствие идентификаторов кварталов строкам и столбцам матрицы;
- учёт прироста вместимости, в том числе нескольких школ в одном квартале;
- допустимы только положительные целые значения вместимости (0, −5, 1.5, "abc", true отклоняются);
- сценарии не меняют исходные массивы, матрицу и файлы `data/`;
- автоподбор: ровно один расчёт на каждый квартал, каждый от исходной сети, прирост не накапливается;
- ручное размещение в найденном квартале воспроизводит результат перебора;
- равноценные лучшие варианты, неполный или остановленный перебор, ошибка в одном квартале;
- HTTP-API: коды ошибок и сообщения на русском, раздача интерфейса.
